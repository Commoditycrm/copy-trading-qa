# DEF-A11Y-001 — Form controls without programmatic labels / accessible names

- **Severity:** High (a11y **critical**) · **Priority:** P1 · **Status:** Fixed — Verified (was Confirmed; reproduced ×2, both a11y-suite runs) · **Date:** 2026-08-04
- **WCAG:** 1.3.1 Info & Relationships, 4.1.2 Name/Role/Value (Level A) · **axe rules:** `label`, `select-name`
- **Confirming tests:** `A11Y-SCAN` (page-scans.spec.ts) · **Environment:** local-qa full stack, Chromium
- **Source:** frontend forms (labels present visually but not programmatically associated; `<select>` without an accessible name)

## Summary
Several form controls have no programmatically-associated label or accessible name, so assistive tech
announces them as unlabeled ("edit text", "combo box"). axe reports **critical** `label` / `select-name`
violations on:

| Page | Rule | Count |
|---|---|---|
| `/register` | `label` | 1 |
| `/settings` | `label` | 1 |
| `/settings` | `select-name` | 3 |
| `/trade-panel` | `label` | 1 |
| `/admin` | `label` | 1 |

## Reproduction
1. Load the page (authenticated where required — synthetic `@qa.kopyya.dev`).
2. Run axe-core with WCAG 2.0/2.1 A+AA tags.
3. Observe the `label` / `select-name` violations (critical).

Deterministic; reproduced on both a11y-suite runs.

## Impact
Screen-reader and voice-control users cannot reliably identify or target these inputs — notably the
`/settings` selects (×3) and the register/trade-panel/admin text inputs. This blocks form completion for
those users.

## Suggested fix (app team — app repo is read-only here)
Associate every control with a label: `<label htmlFor>` + input `id`, or wrap the input in its `<label>`,
or add `aria-label`/`aria-labelledby`. Give each `<select>` an accessible name. The QA scan baseline
(`KNOWN` map in `a11y/tests/page-scans.spec.ts`) lists these rules per page; remove a rule from the baseline
once fixed and the scan then guards the fix.

## Resolution — Fixed — Verified (2026-08-06)
- **Fixed on:** application `origin/main` @ `d8724f5`. **Fix:** form controls given programmatic labels / accessible names (commit `2c94e39`).
- **Verification:** the a11y suite (axe-core) passes with 0 `label`/`select-name` violations on the affected pages. Re-verified twice on a fresh migrated DB (Alembic-from-zero, fake broker, no QA remediation). See `docs/VERIFICATION_NOTES.md`.

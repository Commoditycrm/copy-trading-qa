# DEF-A11Y-002 — Insufficient text/UI colour contrast

- **Severity:** Medium (a11y **serious**) · **Priority:** P2 · **Status:** Confirmed (reproduced ×2, both a11y-suite runs) · **Date:** 2026-08-04
- **WCAG:** 1.4.3 Contrast (Minimum), Level AA · **axe rule:** `color-contrast`
- **Confirming tests:** `A11Y-SCAN` (page-scans.spec.ts) · **Environment:** local-qa full stack, Chromium (light theme)

## Summary
Text/foreground elements fall below the WCAG AA 4.5:1 (3:1 for large text) contrast ratio. axe reports
**serious** `color-contrast` violations on:

| Page | Count |
|---|---|
| `/terms` | 3 |
| `/privacy` | 3 |
| `/brokers` | 1 |
| `/settings` | 1 |
| `/trade-panel` | 1 |
| `/admin` | 1 |

## Reproduction
Load each page and run axe-core (WCAG A+AA); observe `color-contrast` violations. Deterministic; reproduced
on both a11y-suite runs. (Scanned in the default/light theme; the specific low-contrast nodes are attached
to each test as `axe-*` evidence.)

## Impact
Low-vision users and users in bright/glare conditions cannot read the affected text (legal pages, broker/
settings/admin UI, trade-panel labels).

## Suggested fix (app team)
Raise the foreground/background contrast of the flagged tokens to ≥4.5:1 (≥3:1 for ≥18pt/14pt-bold).
Audit the theme colour tokens rather than per-element. Remove `color-contrast` from a page's `KNOWN`
baseline once fixed.
